The unified PID probe — and what each model's old probe did

Companion to dino/docs/unified_pid_probe.md (usage) and dino/docs/unified_probe_results.md (results, 2026-07-02). This page explains why the re-evaluation was needed: what the new probe does, what each model's old probe did differently, and which of those differences turned out to matter.

1. The task, common to everything

Per-pixel PID on DUNE wire-plane sparse data: every reco voxel (channel, tick, charge) gets a 3-class label {track, shower, other} derived from the per-pixel PDG truth by pdg_to_pixel_class() (μ/p/π → track; e± and large-γ EM clusters → shower; γ blips and the rest → other; no-truth pixels dropped). A probe freezes the SSL backbone, extracts a feature per voxel, fits a small head on the features, and reports held-out macro-F1. The probe measures the representation — the backbone never sees the labels.

Every probe (old and new) reports the same four numbers:

2. What the unified probe is

dino/diagnostics/ab_pid_probe.py (ported from WC_FM_DINO; see that repo's docs/28_polarmae_intrinsic_eval_leakage.md). Two properties define it:

2.1 Leakage-free event-level split

Whole events are split 80/20 first; per-pixel examples are pooled afterwards, within each side: 

uniq_events = np.unique(keys, axis=0)        # keys = (file_idx, event_idx) per pixel
perm        = rng.permutation(len(uniq_events))
train_set   = set(map(tuple, uniq_events[perm[:int(0.8 * len(uniq_events))]]))
is_train    = np.array([tuple(k) in train_set for k in keys])

No event's pixels can appear on both sides. The alternative — pooling voxels across events and permuting the pooled array — lets the head partially memorize each event's geometry, topology and local charge pattern through spatially-smooth features, and inflates macro-F1 by ~15 points. That inflation is a property of the protocol, not of the representation.

2.2 One code path for every model

A native DINO checkpoint (--ckpts, live forward pass) and any foreign model's precomputed per-voxel feature export (--external, a CSR .npz of coords / feat / offsets) flow through the same functions: coordinate matching (_match_align_label) → PDG labeling → raw floor → event-level split → StandardScaler → LinearSVC / MLP. Only the source of (feature, coord) pairs differs per run, so cross-architecture numbers are comparable by construction.

Two built-in sanity mechanisms:

  • Alignment gate — model-output rows are joined to truth rows by (channel, tick) per event, and the run aborts if the match rate falls below 0.95 (default). All seven 260702 runs matched at 1.0000.
  • Identical raw floors — because every run scores the same events under the same split, voxel_svm_raw/sft_raw must come out identical across rows (0.402 / 0.485). In the old table the floors scattered 0.43–0.53 across pipelines, a visible symptom of protocol heterogeneity.

3. The old probes, model by model

mae — training-time offline-pool probe (event-level, no leak)

The v3 headline numbers came from mae/scripts/train_mae.py's per-epoch probe: the SFT dataset is split into disjoint event subsets up front (Subset over dataset indices), then _collect_sft_pool drains each side separately into 5000/class voxel pools; SVM + a 3-layer BN MLP (DensePixelHead) are fit on the train pool and scored on the val pool. 64-d features, log1p charge norm. Clean split — mae's number moved up slightly (0.674 → 0.725 sft) under the unified probe, for benign protocol reasons (different head, different events, per-run scaler).

sparseformer — same mae probe (event-level, no leak)

All sparseformer numbers (R1 shapes, R2 capacity sweep) came from the same training-time offline-pool probe, so they were also leakage-free. What did not survive the unified re-run is the capacity conclusion: the old protocol showed w256 (19.5M) at 0.769 vs combo (1.27M) at 0.722 — a +0.047 "width win". The unified probe scores them 0.734 vs 0.749 (sft) and 0.700 vs 0.698 (svm): a tie, with combo ahead on the MLP probe. The width win was the same size as ordinary cross-protocol variance, and it vanished. Lesson: differences of ~0.03–0.05 between separately-run probes are not conclusions; only within-one-probe comparisons are.

dino — run_probes.py (image-level, no leak)

dino/diagnostics/run_probes.py (built for the 260528 dino evaluation) splits at the image level before pooling, applies the DINO FeatureLogTransform norm, and fits the same SVM + BN-MLP pair on 5000/class pools. Clean split; teacher and student probed separately. Under the unified probe dino moved up ~0.05 (0.719 → 0.768 sft; 0.655 → 0.713 svm), same benign reasons as mae. The unified probe's --ckpts path is essentially this probe's extraction plus the shared fitting code — ab_pid_probe adds the external-model path and the explicit coordinate gate.

polarmae & larmamba — APA2DProbeCallback (pixel-level split → leak)

Both token models used PoLAr-MAE's probe callback (polarmae/eval/probes.py), at training time and in every offline eval (larmamba/eval_quant.py included). Its pipeline: drain the probe loader, K-NN-upsample token features to voxels (_extract_per_voxel_features), pool per-class capped samples across events — and then split: 

def _split(self, vb, rng):                  # polarmae/eval/probes.py:464
    perm = rng.permutation(n)               # n = pooled PIXELS, all events mixed
    cut  = int(self.train_frac * n)
    return vb[perm[:cut]], vb[perm[cut:]]   # same event on both sides

That is a pixel-level split: ~80% of every event's pooled pixels land in train and ~20% in val. It interacts badly with exactly this feature type: each voxel's feature is an inverse-distance blend of its ≤5 nearest token vectors, so all voxels in a neighbourhood share nearly the same feature. A head that memorizes "this token-blend ⇒ track" from an event's train pixels scores its val pixels for free.

Measured size of the leak: polarmae 0.933/0.940 → 0.783/0.800 and larmamba 0.940/0.929 → 0.782/0.805 (sft/svm) — −0.13 to −0.15, right in the ~15-point band WC_FM_DINO docs/28 measured for spatially-smooth features under pixel-level splits. The sparse-CNN models, whose old probes split by event/image, did not fall.

5. Takeaways

  1. The ranking survives, the story changes. polarmae ≈ larmamba (0.78–0.80) > dino (0.71–0.77) ≈ sparseformer (0.70–0.75) > mae (0.64–0.72). The tokenizer+transformer edge over sparse-CNNs is ~0.03–0.09, not ~0.2, and is concentrated in shower ID (per-class F1 0.77 vs 0.51–0.65).
  2. larmamba = polarmae is robust — it holds under both protocols (0.805 vs 0.800 svm unified).
  3. Retracted: "sparse-CNN caps at ~0.77, tokenizer needed for 0.9+" (nothing reaches 0.9 honestly) and "width scaling lifted sparseformer +0.047" (protocol variance).
  4. Protocol rules going forward: compare models only inside one probe run (ab_pid_probe, one JSON); never compare numbers across differently-configured probes; treat pixel-level splits of pooled voxel features as invalid for spatially-smooth representations.
